3. The Starter Code: "Local Repo Indexer"
This script scans your directory, ignores non-python files, and builds a persistent database on your computer.

Python
import os
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader, StorageContext, Settings
from llama_index.vector_stores.chroma import ChromaVectorStore
from llama_index.embeddings.google_genai import GeminiEmbedding
from llama_index.llms.google_genai import GoogleGenAI
import chromadb
from dotenv import load_dotenv

load_dotenv()

# 1. CONFIGURE MODELS (The 2026 Global Settings)
# We use Gemini for both Thinking (LLM) and Searching (Embeddings)
Settings.llm = GoogleGenAI(model="models/gemini-2.0-flash")
Settings.embed_model = GeminiEmbedding(model_name="models/text-embedding-004")

def build_codebase_index(repo_path: str):
    # 2. LOAD DATA
    # SimpleDirectoryReader scans the folder. 
    # required_exts ensures we only read Python files.
    reader = SimpleDirectoryReader(
        input_dir=repo_path,
        recursive=True,
        required_exts=[".py"],
        exclude_hidden=True
    )
    documents = reader.load_data()
    print(f"Loaded {len(documents)} Python files.")

    # 3. SETUP LOCAL STORAGE (ChromaDB)
    # This creates a folder called './chroma_db' where your 'brain' lives.
    db = chromadb.PersistentClient(path="./chroma_db")
    chroma_collection = db.get_or_create_collection("my_codebase")
    
    vector_store = ChromaVectorStore(chroma_collection=chroma_collection)
    storage_context = StorageContext.from_defaults(vector_store=vector_store)

    # 4. INDEXING
    # This sends your code to Gemini to turn it into math (vectors)
    index = VectorStoreIndex.from_documents(
        documents, 
        storage_context=storage_context,
        show_progress=True
    )
    
    print("Indexing Complete! Database saved to ./chroma_db")
    return index

# RUN IT
if __name__ == "__main__":
    # Replace with the path to your real project
    MY_PROJECT_PATH = "./my_git_project" 
    build_codebase_index(MY_PROJECT_PATH)
4. Key "Developer" Insights for Day 1
Why text-embedding-004? In 2026, this model is specifically tuned to understand code syntax. It knows that def in Python is related to a "Function" or "Action."

ChromaDB Persistence: Notice PersistentClient. This means you only have to index your code once. Tomorrow, we can just load the database and start asking questions instantly without paying for embeddings again.

Privacy: Since this is a local vector store, your code remains on your machine. Only the "Vectors" (numbers) and the specific chunks used for answering questions are sent to the AI API.

2. The Day 2 Code: "Codebase Query Engine"
This script connects to your existing database and sets up a Streaming Query Engine. Streaming is essential because it makes the AI feel much faster by showing text as it is generated.

Python
import os
import chromadb
from llama_index.core import VectorStoreIndex, StorageContext, Settings
from llama_index.vector_stores.chroma import ChromaVectorStore
from llama_index.embeddings.google_genai import GeminiEmbedding
from llama_index.llms.google_genai import GoogleGenAI
from dotenv import load_dotenv

load_dotenv()

# 1. SETUP MODELS (Must match Day 1 settings)
Settings.llm = GoogleGenAI(model="models/gemini-2.0-flash")
Settings.embed_model = GeminiEmbedding(model_name="models/text-embedding-004")

def query_my_codebase(user_query: str):
    # 2. CONNECT TO PERSISTENT STORAGE
    db = chromadb.PersistentClient(path="./chroma_db")
    chroma_collection = db.get_or_create_collection("my_codebase")
    
    # 3. LOAD THE INDEX
    vector_store = ChromaVectorStore(chroma_collection=chroma_collection)
    index = VectorStoreIndex.from_vector_store(vector_store)

    # 4. CREATE STREAMING ENGINE
    # similarity_top_k=5 means the AI looks at the 5 most relevant code snippets
    query_engine = index.as_query_engine(streaming=True, similarity_top_k=5)

    # 5. EXECUTE & STREAM
    print(f"\nQuerying: {user_query}\n" + "-"*30)
    response = query_engine.query(user_query)
    
    # Print the response word-by-word
    response.print_response_stream()
    return response

if __name__ == "__main__":
    # Example Questions to try:
    # 1. "Explain the high-level architecture of this project."
    # 2. "Find all functions related to authentication."
    # 3. "How do I add a new API endpoint following current patterns?"
    
    query = input("Ask a question about your code: ")
    query_my_codebase(query)

The "Context" Advantage: Notice similarity_top_k=5. You can increase this if your project is huge, but 5 is usually the "sweet spot" for balancing accuracy and speed.

To truly act like a GenAI Engineer, you need to ensure your AI is transparent. In 2026, "Source Citations" are the best way to prevent hallucinations and build trust with your users.

Instead of the AI just saying, "The auth logic is in auth.py," we want it to say: "The auth logic is handled in the validate_token function [Source 1], which checks the JWT expiration [Source 2]."

1. The Citation Workflow
We will use the CitationQueryEngine. This is a specialized LlamaIndex engine that automatically breaks your code into "numbered nodes" and forces the LLM to reference them.

[2] citations -> 5. Final response with clickable file paths.]

2. The Day 2 Upgrade: Code with Citations
This script loads your existing ./chroma_db and uses the specialized CitationQueryEngine.

Python
import os
import chromadb
from llama_index.core import VectorStoreIndex, StorageContext, Settings
from llama_index.vector_stores.chroma import ChromaVectorStore
from llama_index.embeddings.google_genai import GeminiEmbedding
from llama_index.llms.google_genai import GoogleGenAI
from llama_index.core.query_engine import CitationQueryEngine

# 1. SETUP (Must be consistent with Day 1)
Settings.llm = GoogleGenAI(model="models/gemini-2.0-flash")
Settings.embed_model = GeminiEmbedding(model_name="models/text-embedding-004")

def query_with_sources(user_query: str):
    # 2. LOAD STORED INDEX
    db = chromadb.PersistentClient(path="./chroma_db")
    chroma_collection = db.get_or_create_collection("my_codebase")
    vector_store = ChromaVectorStore(chroma_collection=chroma_collection)
    index = VectorStoreIndex.from_vector_store(vector_store)

    # 3. CONFIGURE CITATION ENGINE
    # citation_chunk_size: How small the cited snippets should be
    query_engine = CitationQueryEngine.from_args(
        index,
        similarity_top_k=3,
        citation_chunk_size=512, 
        streaming=True
    )

    # 4. EXECUTE
    response = query_engine.query(user_query)
    
    print(f"\nAI RESPONSE:\n" + "="*30)
    response.print_response_stream()
    
    # 5. PRINT THE ACTUAL SOURCE METADATA
    print(f"\n\nSOURCES USED:\n" + "-"*30)
    for i, node in enumerate(response.source_nodes):
        # Accessing the metadata we saved during Day 1
        file_name = node.node.metadata.get("file_name", "Unknown")
        file_path = node.node.metadata.get("file_path", "Unknown")
        
        print(f"[{i+1}] File: {file_name}")
        print(f"    Path: {file_path}")
        # print(f"    Snippet: {node.node.get_content()[:100]}...") # Optional: see the text

if __name__ == "__main__":
    query = input("Ask about your code (e.g., 'How is the API secured?'): ")
    query_with_sources(query)
3. Why this is a "GenAI Engineer" Pattern
Verification: You can now verify if the AI is "making things up." If it cites [1], you can look at the Sources Used section and see exactly which file it read.

Metadata Power: Notice node.node.metadata. During Day 1's SimpleDirectoryReader step, LlamaIndex automatically extracted the file_path. We are now surfacing that hidden data to the user.

Contextual Integrity: By setting a citation_chunk_size, you ensure the AI doesn't just "see" the whole file, but focuses on the specific 512 characters that answer the question.
